# DO IT SERVICES — UI/UX Design Document

## Mobile-First PWA Design System & Interface Architecture

Based on the PRD and operational workflow shared earlier. 

---

# 1. Design Philosophy

## Core Principle

This platform is **not a traditional office software dashboard**.

It is:

* a field operations tool
* used mostly on phones
* used while traveling
* used under time pressure
* used by non-technical staff

So the UI must prioritize:

| Priority | Requirement               |
| -------- | ------------------------- |
| 1        | Speed                     |
| 2        | Simplicity                |
| 3        | Touch friendliness        |
| 4        | Low typing effort         |
| 5        | Offline reliability       |
| 6        | Clear visibility outdoors |
| 7        | One-hand usability        |

---

# 6. Mobile Layout Principles

## IMPORTANT RULES

### Rule 1 — Bottom Navigation Only

Top-heavy navigation is bad for field usage.

Use:

* bottom tabs
* floating action button (FAB)

---

### Rule 2 — Thumb Reachability

Critical buttons must be reachable with one hand.

---

### Rule 3 — Minimal Typing

Prefer:

* dropdowns
* searchable selects
* numeric pads
* quick actions

Avoid:

* long text entry

---

### Rule 4 — Large Touch Targets

Minimum:

* 44px touch height

Ideal:

* 48–56px

---

### Rule 5 — Single Focus Screens

Each screen should do ONE main thing.

Bad:

* overloaded dashboards

Good:

* focused workflows

## Section 3 — Denomination Breakdown

## BEST UX APPROACH

Use card rows like:

```text id="3j8a1v"
₹500   [-]  10  [+]
₹200   [-]   5  [+]
₹100   [-]   8  [+]
```

NOT tiny text inputs.

This dramatically improves:

* speed
* accuracy
* touch usability

---

## Live Calculation

Sticky total bar at bottom:

```text id="2h1ex6"
Entered Total: ₹12,500
Denomination Total: ₹12,500
✓ Matched
```

OR

```text id="pj16m7"
⚠ Difference: ₹500
```

# 17. Design Risks

# Biggest Risk

Trying to make it:

> “too feature rich”

This can destroy usability.

---

# Another Major Risk

Desktop-first thinking.

This app MUST be:

* mobile-first
* field-first
* operational-first

Not:

* corporate dashboard first

# 20. Final Design Recommendation

This app should feel like:

> a lightweight operational fintech tool

—not an ERP system.

If the UI becomes:

* cluttered
* table-heavy
* desktop-centric

then field staff adoption will fail.

The mobile collection workflow is the heart of the product. Everything else is secondary.
